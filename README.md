# Novel Wiki

**从小说全文到可回查出处的原作百科。** 为冷门作品的粉丝整理人物、经历、设定与关系，先建立可编辑的 SQLite 资料库，再制作静态 Wiki 和 SVG 美术。

第一版：**v1.0.0**。主要指令为中文；运行工具使用 Python 标准库。这里的脚本负责保存、分包与校验，小说理解、归并和网站制作由执行 skill 的 agent 完成。

## 使用

下载 [v1.0.0 发布包](https://github.com/Shadose2024/novel-wiki/releases/tag/v1.0.0)，解压后将整个 `novel-wiki` 文件夹放到 Codex 的 skills 目录：默认 `~/.codex/skills/novel-wiki`，设置了 `CODEX_HOME` 时使用其下的 `skills/novel-wiki`。保留子目录；遇到已有版本先备份，勿混合覆盖文件。

也可以在 Codex 中请求：

> 使用 skill-installer 安装 GitHub 仓库 Shadose2024/novel-wiki 的 v1.0.0，路径为 .，安装名为 novel-wiki。

安装后在下一轮对话中调用：

```text
$novel-wiki
请根据我提供的 TXT／EPUB 全文制作原作百科。
这次先完成资料整理：先用少量连续章节试跑，保存到本地 SQLite，
人物条目同时包含档案和连贯经历。输出进度与待查事项，方便继续。
```

继续制作网站时：

```text
$novel-wiki
继续这部作品，读取已有数据库和交接记录，进入静态网站阶段。
默认没有插画，请根据作品气质设计 SVG 和 CSS，并提供本地浏览方式。
```

agent应具备文件读取、终端和写作能力；运行随附工具需 Python 3.10+。TXT／EPUB接入由agent根据环境选择读取方法，skill规定来源定位与完整性，不内置通用电子书解析器。无需配置本项目专用的 API key。

## 工作方式

| 阶段 | 核心工作 | 模型安排 |
|---|---|---|
| A：原作资料 | 分段提取、证据复核、跨章归并、状态确认、条目草稿 | 提醒可用较便宜模型；每次只处理小包和单一任务 |
| B：静态百科 | 信息结构、人物及设定页、搜索互链、SVG与CSS、浏览检查 | 提醒可用预算内擅长前端与视觉的模型 |

每个阶段只提醒一次，沿用用户已选模型。资料保存在每部作品独立的SQLite中，换模型时接着进度做。

- 人物条目兼顾可查的档案与连贯经历，保留日常细节、限制和阶段变化。
- 原文、资料、百科正文分层保存；每条资料有证据，修改有版本和历史。
- 首轮保留判断，随后约10章或情节收束时复核为初步确定；全文结束后无反转的集中采用为事实。计划仍保留计划状态，原文缺失不会因“没反证”而被补全。
- 文件成功入库只说明结构和定位通过，语义仍由模型复核。

## 可运行示例

下面使用仓库中专门编写的两章虚构短文，演示分包、入库、修改、正文引用和导出。示例结果预先编写，**不调用模型，也不用于评价提取准确率**。

```sh
python examples/demo.py --out demo-output
python scripts/wiki.py --db demo-output/wiki.sqlite status --limit 5
python scripts/wiki.py --db demo-output/wiki.sqlite show record D-c1-p001-002-events-01
```

打开 `demo-output/review/qing.md` 查看人物档案和经历；数据库包含证据原文。用新输出目录重跑示例，防止覆盖修改。

开发检查：

```sh
python -m unittest discover -s tests -v
```

## 第一版的验证范围

存储与引用工具有合成数据回归检查；提取指令经过少量中文小说片段的迭代试跑。此前试跑在同一对话中完成，未提供可靠的模型ID、调用成本或独立盲测，因此不宣称特定模型准确率或费用优势。

全文的语义归并、覆盖质量和网页视觉仍需agent执行并检查。章节进度及跨记录关系目前用带历史记录的SQL事务维护；静态站根据作品生成，没有绑定统一网页模板。云端部署、注册和多人协作留待后续需求。

仓库不包含试跑小说、个人数据库或整本原文；示例可随代码使用。公共网站默认仅导出所需条目、必要短引文与出处。
