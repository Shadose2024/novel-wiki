# 阶段A：提取与整理

先用少量相邻章节走通提取、复核、归并和成文，再扩大范围。目标是得到可用的百科条目，记录条数不作为质量指标。

## 分包提取

默认每包负责约2200个正文字符，前一段仅供衔接；按实际模型表现调整。事件与细节分别处理。每次只给公共指令、当前任务和一个阅读包，避免反复附上全书、数据库结构或建站说明。

给提取模型的公共指令：

> 只依据本包原文，提取assigned=true段落的信息，衔接段仅供理解。每项填写段落范围，保留说话人、条件、约数和时间；区分人物判断、计划与已发生的事。名称照原文写，无法判断就保留疑点，不猜别名。小细节也保留，但一次行为不概括为长期性格。广告不提取。用自己的话概括，按下述JSON输出；无结果用空items。

当前任务二选一：

- `events`：行动、变化、明确动因与结果；倒叙保留故事时间，同一事件跨包时只记本包可证明的部分。kind用event或question。
- `details`：人物身份、外貌、习惯、评价、关系，以及地点、组织、物品、技术的描述、条件和限制。保留日常细节，不复述整段剧情。kind用detail、relation或question。

```json
{
  "pack_id": "复制本包id",
  "task": "details",
  "items": [{
    "kind": "detail",
    "title": "简短标题",
    "content": "忠实于原文并保留条件的描述",
    "subject": "原文称呼，不明确时为空字符串",
    "basis": "narration",
    "state": "general",
    "paragraphs": [1, 2],
    "speaker": "人物说法或内心判断的所属者",
    "story_time": "仅填写原文提供的时间线索"
  }]
}
```

`basis`：narration叙述、dialogue说话、thought内心判断、inference整理者推断、question疑问。疑问同时用kind=question。`state`：actual已发生、planned计划、general一般描述、unknown不明。关系可加predicate和object。一项混合多个说话人或多个可独立变化的状态时拆开；同一设定的条件保留在该项中，不拆丢限制。

原文人物自己的推测用thought并记人物，inference只用于整理者额外作出的推断。数值保留原文精度，不能自行添加或去掉“约”“近乎”等限定。当前场景的流程和能力先限定到该阶段。

## 小批量复核

每次给少量草稿和其证据，只执行一项任务：

1. **对照来源。** 核对谁说、谁想、谁看见、谁行动；检查条件、顺序、时间与完成程度。错误局部修正，核对后标记agent_checked。
2. **补漏。** 回看当前包尚未进入资料的身份、物件、行为与设定限制。补漏依据原文，不拿既有记录总数当配额。
3. **跨章整理。** 按一个对象或一个事件检索相邻记录。相同对象、同一时间范围且内容等价时补充证据；有新增条件或状态变化时另存并关联。旧资料继续可追溯，不覆盖阶段变化。

同名不足以合并；别名须有上下文依据。跨章判断依赖后文时记录待查对象、记录ID和缺少的线索，后续相关内容出现时再处理。对真正相互否定的陈述建立contradicts/corrects联系，并按确认规则处理；先后状态变化不算矛盾。

结构错误只重交该条及相关段落；同一问题两次修复仍失败，保留待处理记录并继续独立包。语义错误不能靠重新格式化JSON解决。

## 编写百科条目

优先用已对照原文的资料编写阶段性草稿。人物包含简明介绍、可查的档案、关系与能力、按故事时间衔接的经历；事件叙述交代有依据的原因、行动、结果。地点、组织、技术按实际资料组织栏目。未知项省略，待查事项另列。

保留有辨识度的细节，用连贯叙述串联经历，避免逐章流水账。一次性场景行为明确所属情境；长期特征须有相应依据。判断和初步确定仅用于工作阶段，全文采用为事实后可正常陈述，内部来源仍保留。

正文以[[记录ID]]关联依据。完成一篇人物和一篇非人物条目，检查它们能否回答实际查阅问题，再扩展栏目。验收重点：无凭空补充、条件未丢失、人物与时间归属正确、阶段变化可辨、重要细节可查、正文连贯。

换模型比较时保持原文、任务和评估范围一致，记录可获得的模型与调用信息。已见前轮答案或反馈的结果标为迭代试跑，不称独立对照；结构检查不能替代内容评价。
